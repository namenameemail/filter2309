## Цель

Столбец картинки попадает в звук раз в 100 мс. Шаг курсора короче, промежуточные колонки пропадают. Поднять частоту до шага курсора, но не чаще шага FFT.

Смысл `speed` и `frames` не менять.

- `speed` — миллисекунды одного шага курсора (5…200, по умолчанию 25).
- `frames` — сколько таких шагов на ширину выделения (1…1000, по умолчанию 200). За шаг голова проходит `w / frames` пикселей. Полный проход длится `speed × frames`.

## Сейчас

Шесть объектов `metro 100` в `filter.pd` вызывают `pixelColumntToArray(n)` и пишут `filter1`…`filter6`. Курсор тикает отдельно (`metro`, период задаёт `speed`).

`fillFilterCache` на каждый новый курсор заменяет столбец. В массив Pd попадает только тот, что был в момент metro. При `speed` 25 за 100 мс проходит четыре шага, слышен последний.

Фильтр шума в `noise.pd`: `block~ 512 4`, окно Ханна 512, `rfft~` → кривая `filter` → `rifft~`. На вебе `sr = 44100`.

- Шаг окна: `512 / 4 = 128` сэмплов, около 3 мс.
- Окно: `512 / 44100 ≈ 12` мс. Новая кривая входит со следующим шагом и ещё около окна смешана с предыдущей.
- Быстрее шага окна отдельный спектр не появляется.

## Что сделать

Публиковать столбец каждого выделения не реже, чем раз в его `speed`, и не чаще шага окна (~3 мс). Если за один публикационный интервал курсор шагнул несколько раз, в массив идёт максимум чернил по всем этим шагам, не только последний. `speed` ≥ 100 мс уже не теряет шаги; выигрыш у более короткого `speed`.

Размер FFT и перекрытие не трогать. `frames` по-прежнему только нарезает ширину.

Чтение колонки с холста (PBO) — стоимость. Шесть фильтров остаются независимыми.
