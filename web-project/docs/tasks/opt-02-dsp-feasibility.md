# OPT-02 — Спайк: хватает ли CPU на DSP в wasm

**Статус:** todo  
**Зависит от:** opt-01  
**Блокирует:** opt-03, opt-04, opt-06

## Цель

Доказать, что `filter.pd` в худшем случае (6 выделений, спектр, все `noise.pd`) считается в wasm-потоке быстрее реального времени с запасом.

## Шаги

1. Режим бенчмарка: Pd-поток крутит тики без ограничения кольцом, без графики и Lua-слушателей; 10 с → realtime factor (секунд звука за секунду).
2. То же нативно (libpd, тот же патч) — отношение wasm/native.
3. Профиль DSP (Chrome Performance на воркере): какие объекты дороже (`rfft~/rifft~`, `osc~`, `expr~`, `tabwrite~`).
4. Проверить, что `-O3`, SIMD (`-msimd128`) применимы к libpd; замерить эффект.

## Критерий

- realtime factor ≥ 3 (DSP ≤ 33% ядра) — go;
- 1.5–3 — go только вместе с [opt-06](opt-06-dsp-optimizations.md);
- < 1.5 — no-go в текущем виде, обсуждать компромиссы.
