## Проблема

После шага 22 ([logs/22-pd-thread.md](../logs/22-pd-thread.md)) Pd считает в отдельном pthread, но:

- звук заметно отстаёт от картинки (курсор впереди звука);
- периодически обрывы (underruns 0–3/с в норме, 30–66/с в пиках, fps падает до 12–20).

## Предварительная оценка реальности (по логам шага 22)

| Ресурс | Нужно | Есть сейчас | Вывод |
|---|---|---|---|
| Pd DSP | 689 тиков/с (44100/64) | 750–770 тиков/с, `busy` ≈ 290 мс/с **включая ожидание замка** | чистый DSP < 30% ядра — влезает |
| Отрисовка | ≤ 33 мс/кадр (30 fps) | 9–11 мс avg | влезает с запасом |

Вычислительно задача реальна. Мешает архитектура:

1. **Связка через `sys_lock`.** Lua-слушатели ofelia (draw/update/keys) держат замок Pd весь вызов; Pd-поток на это время стоит. Кадр > ~46 мс → обрыв.
2. **Вывод звука через ScriptProcessor в главном потоке.** Любой долгий кадр задерживает колбэк → глитч, даже если буфер полон.
3. **Задержка цепочки** ≈ 80–110 мс: кольцо 2048 фреймов (46 мс, держится полным) + ScriptProcessor 512 ×1–2 + baseLatency + FFT `block~ 512 4`. Визуальный курсор берётся из Pd «в момент расчёта», а не «в момент звучания».
4. **Пики браузера.** Поток WebGL-предупреждений PBO (`READ-usage buffer…`) совпадает с провалами.

Окончательный вердикт — после [opt-01](opt-01-measurement.md) и [opt-02](opt-02-dsp-feasibility.md).

## Целевая архитектура

```
main thread (rAF)                 Pd pthread                     AudioWorklet (audio thread)
Lua draw/update/input  ──queue──▶ drain msgs → DSP ticks ──SAB ring──▶ process() 128 frames
  ▲  без sys_lock                  без вызовов Lua                     (без main thread)
  └──────────queue (cursors, spectrum, playedFrames)◀──┘
```

- Главный поток никогда не ждёт Pd; Pd никогда не ждёт Lua/GL.
- Вывод звука не зависит от главного потока.
- Курсор рисуется по аудиочасам (сколько фреймов реально сыграно).

## Критерии готовности блока (целевые, уточнить в opt-01)

- 0 underruns за 5 мин в сценарии «6 выделений + спектр»;
- задержка звук↔курсор визуально не заметна (≤ 1 кадр после компенсации), выходная ≤ 50 мс;
- fps стабилен на целевой машине (30 или 60 — решить в opt-01), пауза кадра max ≤ 50 мс;
- главный поток: доля времени на звук ≈ 0.
